# Domain Docs

## Antes de explorar

Leia `GLOSSARY.md` na raiz e os ADRs em `docs/adr/` relacionados
à área de trabalho.

Se esses documentos não existirem, prossiga silenciosamente.
A skill domain-modeling os cria quando termos ou decisões forem definidos.

## Layout

Este repositório usa single-context:

- `GLOSSARY.md`: vocabulário do domínio.
- `docs/adr/`: decisões de arquitetura numeradas.

## Vocabulário

Use os termos definidos no glossário em tickets, propostas e testes.
Se faltar um conceito necessário, reconsidere o termo ou registre
a lacuna para domain-modeling.

## Conflitos com ADRs

Se uma proposta contrariar um ADR, identifique explicitamente
a decisão e explique por que deve ser reconsiderada.
